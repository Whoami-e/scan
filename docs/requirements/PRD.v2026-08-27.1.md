# 文档扫描 App MVP PRD v2026-08-27.1

## 0. 文档版本说明

本文档基于 `docs/requirements/PRD.v2026-08-27.md` 创建，是 2026-08-27.1 版本的 PRD。为避免需求变更覆盖历史上下文，后续新增需求、范围调整、验收口径变化，均应新建版本文档承载，不直接改写旧版本 PRD。

### 0.1 版本管理原则

- 原始 PRD 文件作为历史基线保留，不直接覆盖。
- 新需求、新决策、新验收标准应创建新的版本文档，例如 `PRD.vYYYY-MM-DD.md`。
- 新版本文档可以继承上一版本内容，并在对应章节补充或调整需求。
- 每个版本文档应在开头说明版本日期、来源版本和本次主要变化。

### 0.2 本版本主要变化

- 明确 MVP 包含轻量历史文档列表管理。
- 明确多页扫描采用逐页拍摄、逐页裁剪确认、逐页加入文档的流程。
- 明确 PDF 默认输出为 A4 页面、图片铺满可打印区域并保留 10mm 白边。
- 明确导出 PDF 后仍保留可继续编辑的扫描工程。
- 明确 MVP 阶段仅保留本地日志，不接入远程埋点或远程崩溃上报。
- 明确 Android 版本策略按主流设备支持，建议最低 Android 10 / API 29+。
- 明确 PDF 默认保存在 App 沙盒内，不主动写入系统下载目录。
- 明确卸载 App 后沙盒内扫描工程和 PDF 随 App 数据删除，产品内需要提示用户提前分享重要文件。
- 明确 PDF 重名时由用户选择覆盖或另存一份。
- 明确 PDF 页面方向默认按每页图片方向自动选择，无法判断时由用户选择。
- 明确扫描中断时的临时照片恢复策略。
- 明确图片处理尺寸、PDF 压缩质量和 20 页 PDF 目标体积。
- 明确 MVP 不提供导出质量选项、自动拍照、搜索筛选和删除撤销。
- 明确相册支持多选导入，但仍逐页裁剪和增强确认。
- 明确页面重新编辑基于原图重新生成处理图。
- 明确本地日志保留周期、大小上限和敏感信息禁止项。
- 明确 MVP 测试设备、材料、拍摄环境和指标采集方式。

## 1. 背景

用户需要一个类似“全能扫描王”的移动端文档扫描 App。MVP 阶段先支持 Android，后续预留 iOS 版本扩展空间。第一版不做 OCR，不做云同步，核心目标是让用户可以通过手机拍照快速生成清晰、规整的 PDF 文档。

## 2. 产品目标

### 2.1 MVP 目标

- 支持用户拍摄纸质文档、票据、证件、笔记等内容。
- 自动识别文档边缘，并生成矫正后的扫描图片。
- 支持用户手动调整文档四角。
- 支持基础图像增强，让扫描结果更接近扫描仪效果。
- 支持多页文档管理，并导出为 PDF 文件。
- 支持将 PDF 保存到 App 沙盒内，并通过系统分享能力发送出去。
- 支持本地历史文档列表管理，用户可以打开、重命名、删除、继续编辑并重新导出已有文档。
- 导出 PDF 后保留扫描工程，用户后续仍可调整页面并再次导出。

### 2.2 非目标

MVP 阶段不包含以下能力：

- OCR 文字识别
- 搜索 PDF 内容
- 云端同步
- 登录/注册
- 会员付费
- 团队协作
- 电子签名
- 批注编辑
- 水印模板
- 自动分类归档
- 远程埋点
- 远程崩溃上报

## 3. 目标用户

### 3.1 主要用户

- 学生：扫描课堂讲义、手写笔记、作业、资料。
- 职场用户：扫描合同、发票、报销单、会议资料。
- 个体经营者：扫描收据、单据、身份证明材料。

### 3.2 用户核心诉求

- 扫描速度快。
- 文件看起来清楚、规整。
- PDF 容易分享。
- 不需要复杂账号体系。
- 本地处理，隐私风险低。

## 4. MVP 核心场景

### 4.1 单页扫描

用户打开 App，点击扫描按钮，拍摄一张纸质文档。系统自动识别文档边界，用户确认后生成一张扫描页，并可以导出为 PDF。

### 4.2 多页扫描

用户连续拍摄多页文档。MVP 阶段采用逐页确认流程：每拍摄一页，都进入裁剪确认和图像增强流程，用户确认后再加入当前文档。用户可以调整顺序、删除错误页面，并最终合成为一个 PDF。

### 4.3 手动修正

当自动识别边缘不准确时，用户可以拖动四个角点，手动调整裁剪范围，然后重新生成扫描结果。

### 4.4 文件分享

用户完成扫描后，可以为 PDF 命名，并通过 Android 系统分享面板发送到微信、邮箱、网盘或其他 App。

### 4.5 历史文档继续编辑

用户在首页打开历史文档，可以查看已扫描页面，继续新增页面、调整顺序、删除页面、修改文件名，并重新导出 PDF。导出 PDF 不删除扫描工程，只有用户主动删除文档时才清理对应本地资源。

## 5. 功能需求

### 5.1 首页

首页用于展示本地扫描文档列表。

#### 功能

- 展示最近创建的扫描文档。
- 每个文档显示封面缩略图、标题、页数、创建时间。
- 默认按最近更新时间倒序展示文档。
- 支持新建扫描。
- 支持打开已有文档。
- 支持重命名已有文档。
- 支持删除本地文档。
- 支持继续编辑已有文档。
- 支持对已有文档重新导出 PDF。
- 支持进入轻量设置页。
- MVP 不提供搜索、筛选或排序切换。

#### 验收标准

- 用户首次打开 App 时，可以看到空状态和明显的扫描入口。
- 用户创建文档后，首页可以展示新文档。
- 用户可以打开历史文档并继续编辑页面。
- 用户重命名文档后，首页展示新名称。
- 用户删除文档后，该文档不再出现在首页。
- 用户删除文档后，相关原图、处理图、缩略图和 PDF 文件应被一并清理。
- 用户新增、编辑、重新导出文档后，该文档应按最近更新时间回到列表靠前位置。
- 首页不出现搜索框、筛选器或排序切换入口。

### 5.2 扫描拍摄页

扫描拍摄页用于调用相机拍摄文档。

#### 功能

- 支持相机预览。
- 支持手动拍照。
- MVP 不支持自动拍照。
- 支持闪光灯开关。
- 支持从相册导入图片。
- 支持从相册多选导入图片。
- 拍照后进入裁剪确认流程。
- 相册多选导入后，按选择顺序逐页进入裁剪确认和图像增强流程。

#### 验收标准

- 用户允许相机权限后，可以正常看到相机预览。
- 用户拒绝相机权限时，页面展示权限说明和跳转设置入口。
- 用户点击拍照后，可以进入裁剪确认页。
- 用户可以从相册选择图片进入裁剪确认页。
- 用户一次从相册选择多张图片后，App 按顺序逐页处理，每页都需要用户确认裁剪和增强后再加入文档。
- 拍摄页可以实时提示检测到的文档边缘，但最终采集必须由用户点击拍照触发。

### 5.3 边缘识别与裁剪确认页

裁剪确认页用于确认文档边界。

#### 功能

- 自动识别文档四个角点。
- 在图片上展示可拖动的四角控制点。
- 支持用户手动调整四角。
- 支持重新检测边缘。
- 支持确认裁剪。
- 支持返回重新拍摄。

#### 验收标准

- 正常光照下，A4 纸文档可以被自动识别出边缘。
- 用户可以拖动四角完成精确修正。
- 用户确认后，系统生成透视矫正后的扫描图片。
- 自动识别失败时，系统仍允许用户手动框选。

### 5.4 图像增强页

图像增强页用于让扫描结果更清晰。

#### 功能

- 支持原图模式。
- 支持增强模式。
- 支持灰度模式。
- 支持黑白模式。
- 支持旋转图片。
- 支持重新裁剪。
- 支持确认加入文档。
- 已加入文档的页面重新编辑时，基于原图、四角坐标、旋转角度和增强模式重新生成处理图。

#### 验收标准

- 用户可以在不同滤镜之间切换。
- 滤镜切换后，预览图可以及时更新。
- 用户确认后，当前页加入文档页面列表。
- 图片旋转后，导出的 PDF 页面方向正确。
- 用户重新裁剪或切换增强模式后，处理图重新生成，不因多次编辑导致画质持续下降。

### 5.5 多页管理页

多页管理页用于管理当前文档中的扫描页。

#### 功能

- 展示当前文档全部页面缩略图。
- 支持继续扫描。
- 支持从相册继续导入。
- 支持删除页面。
- 支持调整页面顺序。
- 支持点击页面重新编辑。
- 支持进入 PDF 导出。

#### 验收标准

- 用户可以连续添加多页。
- 用户删除页面后，页数正确更新。
- 用户调整顺序后，PDF 导出顺序与页面列表一致。
- 至少支持 20 页文档的正常管理和导出。

### 5.6 PDF 导出页

PDF 导出页用于配置并生成 PDF 文件。

#### 功能

- 支持编辑 PDF 文件名。
- 支持预览文档页数。
- 默认生成 A4 页面 PDF。
- 每页 PDF 默认根据扫描图方向自动选择竖版 A4 或横版 A4。
- 当系统无法可靠判断页面方向时，在导出页提示用户选择竖版或横版。
- 每页扫描图等比缩放，尽量铺满 A4 可打印区域。
- 每页保留 10mm 白边。
- MVP 不提供导出质量选项，统一使用默认推荐质量。
- 支持生成 PDF。
- 默认将 PDF 保存到 App 沙盒内。
- 支持调用 Android 系统分享面板。
- 导出完成后提供“打开预览”和“分享”两个入口。
- 导出后保留扫描工程，允许后续继续编辑并重新导出。
- 检测到同名 PDF 时，弹窗询问用户选择覆盖原文件或另存一份；选择另存时可自动追加序号。

#### 验收标准

- PDF 文件名不能为空。
- PDF 可以成功生成并打开预览。
- 多页 PDF 页序正确。
- PDF 页面默认为 A4，扫描图片不被拉伸变形。
- 每页 PDF 保留 10mm 白边。
- 横向扫描图应导出为横版 A4，竖向扫描图应导出为竖版 A4；无法判断方向时以用户选择为准。
- 分享到第三方 App 时，接收方可以正常识别 PDF 文件。
- 导出完成后，用户可以打开 PDF 预览或调用系统分享面板。
- 用户重新导出同一文档时，可以生成新的 PDF 文件并更新文档记录。
- 同名 PDF 的覆盖或另存行为必须符合用户在弹窗中的选择。
- 首页不作为 PDF 文件管理器，只展示可继续编辑的扫描工程文档。

### 5.7 设置页

设置页用于承载轻量说明和问题排查入口，不承载复杂账号或云端能力。

#### 功能

- 展示本地保存说明。
- 提示用户卸载 App 后，App 内扫描工程和 PDF 会随 App 数据删除。
- 支持用户主动导出本地日志。
- 展示 App 版本号。
- MVP 不支持登录、云同步、会员、主题切换或复杂配置。

#### 验收标准

- 用户可以在设置页看到本地保存和卸载数据删除说明。
- 用户可以主动导出本地日志文件。
- 导出的日志不包含文档标题、文件名、完整本地路径、图片内容或 PDF 内容。
- 设置页不出现账号、云同步、会员付费等 MVP 非目标功能入口。

## 6. 推荐用户流程

1. 用户打开 App。
2. 用户点击“扫描”。
3. App 请求相机权限。
4. 用户拍摄文档。
5. 系统自动识别文档边缘。
6. 用户调整四角并确认。
7. 用户选择图像增强模式。
8. 用户将页面加入当前文档。
9. 用户选择继续扫描或导出 PDF。
10. 用户命名 PDF 并导出。
11. 导出完成后，用户可以打开预览或通过系统分享面板分享 PDF。

## 7. 技术方向

### 7.1 技术栈

- 前端框架：React Native
- MVP 平台：Android
- Android 版本策略：按主流设备支持，建议最低 Android 10 / API 29+。
- Target SDK：跟随 Google Play 当前上架要求。
- 后续扩展：iOS
- 扫描处理：Android 原生模块
- 图像处理：OpenCV 或同类图像处理库
- PDF 生成：Android 原生 PDF 能力或 PDFBox-Android
- 本地存储：App 沙盒目录
- 本地日志：MVP 阶段仅保留本地运行日志和错误日志，不接入远程埋点或远程崩溃上报。
- 默认 PDF 保存位置：App 沙盒目录，不主动写入系统 Downloads/下载目录。
- 文件分享：优先通过 Android 系统分享能力向外部 App 临时授权访问导出的 PDF。

### 7.2 模块划分

#### React Native 层

- 页面导航
- 文档列表
- 页面管理
- 状态管理
- PDF 分享入口
- 错误提示

#### Android 原生层

- 相机能力
- 图片裁剪
- 透视矫正
- 图像增强
- PDF 文件生成

#### Native Module 接口建议

- `detectDocumentEdges(imagePath)`：检测文档边缘。
- `cropAndWarp(imagePath, corners)`：根据四角裁剪并透视矫正。
- `enhanceImage(imagePath, mode)`：应用图像增强模式。
- `createPdf(pageImagePaths, outputName, options)`：将多张图片合成为 PDF，`options` 至少包含 A4 方向、白边和图片压缩质量。
- `shareFile(filePath)`：调用系统分享能力。
- `openFile(filePath)`：调用系统能力打开 PDF 预览。
- `exportLogs()`：由用户主动触发，导出本地非敏感日志。

## 8. 数据结构

### 8.1 Document

```json
{
  "id": "doc_001",
  "title": "扫描文档 20260827-1430",
  "createdAt": "2026-08-26T17:00:00+08:00",
  "updatedAt": "2026-08-26T17:10:00+08:00",
  "lastExportedAt": "2026-08-26T17:12:00+08:00",
  "pageCount": 3,
  "coverImagePath": "/local/path/page_001.jpg",
  "pdfPath": "/local/path/doc_001.pdf",
  "pdfFileSize": 2457600,
  "pdfOrientationPolicy": "auto",
  "status": "exported"
}
```

#### 字段说明

- `title`：新建文档默认命名为 `扫描文档 yyyyMMdd-HHmm`，用户可在首页或导出页重命名。
- `pdfPath`：指向 App 沙盒内最近一次成功导出的 PDF。
- `pdfOrientationPolicy`：默认值为 `auto`，表示按每页扫描图方向自动选择 A4 竖版或横版。
- `status`：用于区分草稿、处理中、已导出等状态。

### 8.2 ScanPage

```json
{
  "id": "page_001",
  "documentId": "doc_001",
  "originalImagePath": "/local/path/original_001.jpg",
  "processedImagePath": "/local/path/processed_001.jpg",
  "thumbnailPath": "/local/path/thumb_001.jpg",
  "order": 1,
  "enhanceMode": "enhanced",
  "rotation": 0,
  "corners": [
    { "x": 42, "y": 80 },
    { "x": 1030, "y": 76 },
    { "x": 1054, "y": 1480 },
    { "x": 36, "y": 1492 }
  ],
  "originalWidth": 1080,
  "originalHeight": 1600,
  "processedWidth": 1240,
  "processedHeight": 1754,
  "fileSize": 734003,
  "pdfPageOrientation": "portrait",
  "status": "processed"
}
```

#### 字段说明

- `originalImagePath`：保留原图，用于后续重新裁剪和重新增强。
- `processedImagePath`：由原图、四角坐标、旋转角度和增强模式生成，重新编辑时应重新生成。
- `pdfPageOrientation`：当前页面导出 PDF 时使用的页面方向，可为 `portrait` 或 `landscape`。

### 8.3 本地文件保留策略

- 每个文档保留扫描工程数据，包括原图、处理图、缩略图、页面顺序、裁剪四角、旋转角度和增强模式。
- 导出 PDF 后，不删除扫描工程。
- 用户重新导出 PDF 时，更新文档的 `pdfPath`、`pdfFileSize` 和 `lastExportedAt`。
- 用户删除文档时，应同时删除该文档关联的原图、处理图、缩略图和 PDF 文件。
- App 不应在未告知用户的情况下清理仍可编辑的扫描工程。
- 临时处理文件可以在处理完成后清理，但不能影响用户继续编辑已保存文档。
- PDF 默认保存在 App 沙盒内，不主动保存到系统 Downloads/下载目录。
- 用户卸载 App 后，App 沙盒内的扫描工程、原图、处理图、缩略图和已导出的 PDF 会随 App 数据删除。
- App 应在设置页或合适位置提示用户：重要文件请先通过分享保存到其他 App 或位置。
- 用户主动取消扫描、主动放弃恢复或删除文档后，对应临时文件和工程文件应及时清理。

### 8.4 临时草稿策略

- 已确认加入文档的页面必须保存。
- 未确认裁剪的临时照片短期保留，用于系统中断、App 切后台或异常退出后的恢复。
- 用户下次进入扫描流程时，如果存在未确认临时照片，应提示是否恢复。
- 用户选择不恢复、主动取消或主动放弃扫描时，删除对应临时照片。
- 临时照片不得长期堆积，具体清理周期由实现按本地空间和最近使用情况控制，但不得删除已保存工程。

### 8.5 本地日志策略

- MVP 仅保留本地非敏感日志，不接入远程埋点或远程崩溃上报。
- 日志最多保留最近 7 天或 5MB，超过后循环覆盖。
- 日志可记录 App 版本、Android 版本、设备型号、关键操作时间点、错误码和非敏感异常栈。
- 日志不得记录文档标题、文件名、完整本地路径、图片内容、PDF 内容或其他可识别用户文档内容的信息。
- 本地日志只能由用户主动导出。

## 9. 权限需求

### 9.1 Android 权限

- 相机权限：用于拍摄文档。
- 相册读取权限：用于导入图片。
- 文件访问权限：PDF 默认保存在 App 沙盒内，不主动申请外部存储写入权限；分享 PDF 时优先使用 Android 推荐的系统分享能力。
- 本地日志不需要额外敏感权限，不应读取或记录用户文档内容。

### 9.2 权限处理原则

- 只在用户触发相关功能时请求权限。
- 用户拒绝权限后，给出明确提示。
- 不强制用户登录。
- 不上传用户文档。
- MVP 阶段不接入远程埋点或远程崩溃上报。
- 本地日志仅用于排查运行问题，不记录图片内容、PDF 内容、文档标题、文件名、完整本地路径等敏感信息。
- 重要文件只保存在 App 内时，应向用户提示卸载 App 会删除 App 内文件，建议重要 PDF 主动分享或转存。
- 如后续版本需要远程统计或崩溃上报，必须单独补充隐私策略、采集字段和用户告知方案。

## 10. 视觉与交互风格

MVP 视觉风格以 Apple 风格为主要参考方向，结合用户提供的色板与布局准则落地。由于 MVP 先做 Android，本产品不直接照搬 iOS 系统控件，而是在 Android 上实现 Apple 式的清爽、克制、精密和可信赖的工具体验。

整体视觉关键词：

- 干净：页面背景简单，信息密度适中，不堆装饰。
- 精密：对齐、间距、控件状态要稳定，避免粗糙的随意感。
- 轻量：少用重阴影、大渐变、复杂纹理和过度拟物。
- 聚焦：扫描、裁剪、增强、导出这些主流程要清楚突出。
- 专业：文档类工具要像系统级生产力工具，而不是营销型 App。

### 10.1 色板规范

色彩以黑、白、浅灰、石墨灰和蓝色强调色为主。蓝色只用于可点击、主操作、焦点状态和少量品牌强调，不应大面积铺满界面。

#### 10.1.1 核心颜色

| 色值 | 名称 | 角色 | 使用场景 |
|---|---|---|---|
| `#000000` | Absolute Black | 深色锚点 | 相机页沉浸背景、深色模式下的最深背景、扫描取景器外部遮罩 |
| `#FFFFFF` | Pure White Canvas | 主画布 | 首页、文档列表、导出页、浅色模式主背景 |
| `#F5F5F7` | Pale Apple Gray | 浅灰背景 | 分组背景、页面底色、列表分区、轻量工具区 |
| `#1D1D1F` | Near Black Ink | 主文字 | 标题、正文主文本、主要图标 |
| `#6E6E73` | Secondary Neutral Gray | 次级文字 | 辅助说明、时间、页数、空状态副文案、非重点图标 |
| `#0071E3` | Apple Action Blue | 主操作蓝 | 主按钮、确认、导出、扫描入口、当前选中状态 |
| `#0066CC` | Body Link Blue | 链接蓝 | 文档链接、设置入口、权限页中的可点击文本 |
| `#2997FF` | High Luminance Link Blue | 高亮链接蓝 | 深色相机页、深色预览页上的链接或选中状态 |

#### 10.1.2 石墨灰层级

深色界面和沉浸式相机界面使用以下石墨灰层级，避免只用纯黑导致层次不足。

| 色值 | 名称 | 角色 | 使用场景 |
|---|---|---|---|
| `#272729` | Graphite Surface A | 深色基础卡片 | 深色模式下的卡片、相机页底部工具栏 |
| `#262629` | Graphite Surface B | 深色控件分组 | 滤镜选择条、操作组背景 |
| `#28282B` | Graphite Surface C | 深色浮层 | 深色模式弹窗、底部面板 |
| `#2A2A2C` | Graphite Surface D | 深色分隔层 | 深色模式分割、取景器辅助区域 |

#### 10.1.3 颜色使用规则

- 浅色页面默认背景使用 `#FFFFFF`，分组背景使用 `#F5F5F7`。
- 主标题、按钮文字和高优先级图标使用 `#1D1D1F`。
- 次级信息使用 `#6E6E73`，例如“3 页”“刚刚创建”“PDF 2.4 MB”。
- 主操作只使用 `#0071E3`，例如“扫描”“确认”“导出 PDF”。
- 链接和设置跳转使用 `#0066CC`。
- 深色相机页可使用 `#000000` 作为底色，工具栏使用 `#272729` 或 `#262629`。
- 深色界面上的蓝色强调优先使用 `#2997FF`，保证可读性。
- 禁止使用大面积高饱和渐变作为主背景。
- 禁止把所有按钮都做成蓝色。只有当前页面最重要的操作才使用蓝色实心按钮。
- 警告和删除操作可以使用系统红色，但只用于危险操作，不进入品牌色板。

### 10.2 字体与文字层级

Apple 风格的关键不是字体名称本身，而是字号层级清晰、字重克制、排版留白准确。Android 端优先使用系统默认无衬线字体，React Native 可使用 `System` 字体栈；如后续统一跨平台字体，可评估 Inter。

#### 10.2.1 字号建议

| 层级 | 字号 | 字重 | 使用场景 |
|---|---:|---:|---|
| 大标题 | 28-34 | 700 | 首页标题、文档名称编辑页标题 |
| 页面标题 | 22-24 | 700 | 页面顶部标题、主要流程页标题 |
| 分组标题 | 17-20 | 600 | “最近文档”“图像增强”“导出设置” |
| 正文 | 15-17 | 400 | 普通说明、列表主信息 |
| 辅助文字 | 13-14 | 400 | 时间、页数、文件大小、权限说明 |
| 按钮文字 | 15-17 | 600 | 主按钮、底部操作按钮 |
| 元信息 | 11-12 | 400 | 缩略图角标、页码、状态短标签 |

#### 10.2.2 文案风格

- 文案应短、准、直接，不使用夸张营销语。
- 空状态文案不超过两行，并直接引导操作。
- 错误提示要说明发生了什么，以及用户下一步能做什么。
- 按钮文案优先使用动词加对象，例如“导出 PDF”“继续扫描”“重新检测”。
- 删除类操作使用明确对象，例如“删除此页”“删除文档”。

### 10.3 间距与布局准则

参考图中的布局准则：基础单位按 8px 理解，同时允许更细的微步长来做精密对齐。页面应显得开阔、有呼吸感，但工具区域要保持高效，不浪费关键操作空间。

#### 10.3.1 基础间距

- 基础单位：8px。
- 高频间距：2px、4px、6px、7px、8px、9px、10px、12px、14px、17px、20px。
- 组件内部左右 padding 建议：14-20px。
- 列表项上下 padding 建议：12-17px。
- 页面左右安全边距建议：20px。
- 分组之间间距建议：20px 或 24px。
- 底部主操作区与屏幕底部需考虑安全距离。

#### 10.3.2 页面布局

- 首页使用可读核心区域，不做复杂多栏。
- 文档列表采用单列或两列卡片布局，优先保证封面缩略图清楚。
- 扫描页使用全屏相机预览，控制区贴近底部。
- 裁剪页图片主体居中展示，四角控制点始终可见。
- 图像增强页主体为大图预览，工具和滤镜放在底部。
- 多页管理页可以使用缩略图网格，但每个页面项尺寸必须稳定。
- PDF 导出页使用表单式布局，避免营销页式大标题和装饰卡片。

#### 10.3.3 容器规则

- 页面主体内容宽度受约束，避免元素贴边。
- 卡片只用于文档列表、页面缩略图、弹窗和明确的内容容器。
- 不要把卡片嵌套在卡片里。
- 分组背景可以使用 `#F5F5F7`，但页面不应堆太多浮层。
- 控件对齐必须统一，列表中的标题、时间、页数、操作按钮要形成清晰纵向基线。

### 10.4 圆角、边框与阴影

- 主要卡片圆角：12-16px。
- 缩略图圆角：8-12px。
- 底部工具栏圆角：16-20px，仅用于浮层式工具栏。
- 小按钮和图标按钮圆角：10-14px。
- 输入框圆角：10-12px。
- 边框颜色使用浅灰，不使用高对比黑边。
- 阴影要轻，优先用背景层级和边框表达分组。
- 相机页、裁剪页等沉浸界面可以使用半透明深色工具栏，但透明度要稳定，不影响文字可读性。

### 10.5 图标与控件

- 图标使用统一线性风格，线宽保持一致。
- 常见操作优先使用熟悉图标：拍照、闪光灯、相册、旋转、删除、分享、下载、返回、确认。
- 图标按钮点击区域不小于 44x44px。
- 主按钮高度建议 48-56px。
- 次级按钮可使用文字按钮或浅灰底按钮。
- 滤镜选择使用横向分段控件或底部选项条。
- 当前选中状态使用蓝色文字、蓝色描边或蓝色小标识，不要过度依赖大面积填充。
- 危险操作使用红色文字或红色图标，不使用蓝色。

### 10.6 页面级设计要求

#### 10.6.1 首页

- 首页应像轻量文件管理工具，不做营销首页。
- 顶部显示简短标题，例如“扫描”或“文档”。
- 主要扫描入口固定且醒目，可使用底部中央扫描按钮或右下角悬浮扫描按钮。
- 文档列表展示封面缩略图、标题、页数、更新时间。
- 文档列表默认按最近更新时间倒序排列，不展示搜索、筛选或排序切换控件。
- 空状态应直接展示“开始扫描”入口。
- 首页背景优先使用 `#F5F5F7`，文档卡片使用 `#FFFFFF`。

#### 10.6.2 扫描拍摄页

- 使用全屏相机预览，减少文字说明。
- 顶部只保留返回、闪光灯、相册等必要操作。
- 底部保留拍照主按钮，拍照按钮应足够大且视觉居中。
- MVP 阶段拍照必须由用户手动触发，不提供自动拍照开关。
- 取景器中可展示文档边缘提示线，但不能遮挡文档内容。
- 自动检测到文档时，边缘线使用蓝色或白色高亮。
- 低光、抖动、未检测到文档等状态可用简短提示，不要弹窗打断。

#### 10.6.3 裁剪确认页

- 图片主体居中，背景使用深色或浅灰，以突出文档。
- 四个角点必须清楚可见，触控热区大于视觉点。
- 边缘线使用蓝色高亮，和背景保持足够对比。
- 底部操作建议包括“重拍”“重新检测”“确认”。
- 自动识别失败时，不显示错误页，直接进入手动框选。

#### 10.6.4 图像增强页

- 页面主体展示处理后的大图预览。
- 底部工具栏承载原图、增强、灰度、黑白、旋转、重裁剪。
- 滤镜切换要有即时反馈。
- 当前滤镜状态要清楚标识。
- 不同滤镜的命名必须面向普通用户，不使用技术术语。

#### 10.6.5 多页管理页

- 缩略图网格要整齐，页面顺序要清楚。
- 每页显示页码或顺序标识。
- 支持长按或明显入口进行排序。
- 删除页面需要二次确认，避免误删。
- “继续扫描”和“导出 PDF”应作为主要流程按钮，不被次要功能淹没。

#### 10.6.6 PDF 导出页

- 文件名输入区要清楚，默认文件名可基于日期生成。
- 显示页数、预计文件大小或导出质量信息。
- MVP 阶段不展示导出质量选项。
- 主按钮使用“导出 PDF”。
- 导出完成后显示“打开预览”和“分享”两个明确入口。
- 分享失败时保留本地 PDF，并提示用户可以稍后重试。

#### 10.6.7 设置页

- 设置页保持轻量，不做复杂配置中心。
- 页面内容包括本地保存说明、卸载数据删除提醒、本地日志导出入口和版本号。
- 本地保存说明和卸载提醒应短、准、可理解，不使用吓唬用户的表述。
- 日志导出入口应说明日志不包含文档内容。

### 10.7 明暗模式

MVP 应同时定义浅色和深色两套视觉效果。第一版可以优先实现浅色主流程，但代码结构必须支持后续完整深色模式；扫描拍摄页、裁剪页、图像增强页这类沉浸式页面，MVP 阶段即可优先采用深色效果。

#### 10.7.1 浅色效果

浅色效果参考用户提供的 Apple kit 浅色示例：白色主画布、浅灰分组面、黑色大标题、蓝色主按钮、轻边框卡片。

##### 浅色颜色映射

| 用途 | 色值 | 说明 |
|---|---|---|
| 页面主背景 | `#FFFFFF` | 首页、PDF 导出页、设置页等内容型页面 |
| 分组背景 | `#F5F5F7` | 文档列表背景、表单分区、底部工具区域 |
| 卡片背景 | `#FFFFFF` | 文档卡片、页面缩略图卡片、信息模块 |
| 卡片边框 | `#D2D2D7` 或接近浅灰 | 用于轻量分隔，不做厚重描边 |
| 主文字 | `#1D1D1F` | 页面标题、卡片标题、按钮主文字 |
| 次级文字 | `#6E6E73` | 时间、页数、说明、状态描述 |
| 主操作 | `#0071E3` | 扫描、确认、导出 PDF |
| 链接文字 | `#0066CC` | 设置入口、权限跳转、帮助链接 |

##### 浅色界面表现

- 页面应以白色或浅灰为主，不使用强装饰背景。
- 大标题可以大胆，但只用于首页或一级页面，不用于密集工具区。
- 卡片使用浅灰边框和轻微层级感，避免浓重投影。
- 主按钮使用蓝底白字，视觉优先级最高。
- 次级按钮使用浅灰底、细边框或文字按钮。
- 输入框使用白色或浅灰底，聚焦时使用蓝色边框或蓝色光标。
- 标签、状态、页数等元信息使用中性灰，不抢主流程操作。
- 页面底部主操作区域要清楚，但不能厚重到像广告按钮。

##### 浅色页面适用范围

- 首页
- 文档列表
- 多页管理页
- PDF 导出页
- 权限说明页
- 设置页
- 删除确认弹窗

#### 10.7.2 深色效果

深色效果参考用户提供的 Apple kit 深色示例：接近黑色的背景、石墨灰卡片、白色标题、灰色说明文字、蓝色强调操作。

##### 深色颜色映射

| 用途 | 色值 | 说明 |
|---|---|---|
| 页面主背景 | `#000000` | 相机页、裁剪页、图片预览页的沉浸背景 |
| 深色基础表面 | `#272729` | 深色卡片或主要控制面板 |
| 深色控件分组 | `#262629` | 工具栏、滤镜栏、按钮组 |
| 深色浮层 | `#28282B` | 底部弹层、确认面板 |
| 深色分隔层 | `#2A2A2C` | 边界、遮罩、辅助分层 |
| 深色主文字 | `#FFFFFF` | 重要标题、确认按钮文字、关键数字 |
| 深色次级文字 | `#B8BCC6` 或接近浅灰 | 辅助说明、状态描述、非重点信息 |
| 深色强调色 | `#2997FF` | 深色界面中的选中、链接和焦点状态 |

##### 深色界面表现

- 背景应接近黑色，减少环境干扰，让文档图片成为视觉中心。
- 工具栏和卡片使用石墨灰，不直接使用纯黑卡片堆叠。
- 深色模式不应只是把浅色页面反相，需要重新处理层级。
- 大标题、关键状态和主操作文字使用白色。
- 次级说明使用低饱和浅灰，但必须保证可读。
- 深色界面中的蓝色按钮可使用 `#0071E3` 或 `#2997FF`，优先保证对比度。
- 线性图标使用白色或浅灰，禁用态使用更低对比灰色。
- 边框使用深灰描边，不能使用浅色高亮边框破坏沉浸感。
- 图片预览区域周围允许使用暗色遮罩，以突出纸张边界。

##### 深色页面适用范围

- 扫描拍摄页
- 裁剪确认页
- 图像增强页
- PDF 预览页
- 全屏图片查看页

#### 10.7.3 明暗切换策略

- MVP 不强制提供手动主题切换开关，但代码层要预留 theme token。
- 如果读取系统主题，首页、列表、导出页可以跟随系统主题切换。
- 相机页、裁剪页、图像增强页即使在浅色系统主题下，也可以保持深色沉浸效果。
- 深色和浅色必须使用同一套语义 token，不允许在页面内散落硬编码颜色。
- 主题切换时不能导致布局尺寸变化、按钮抖动或文字截断。
- 主题切换后，文档缩略图、扫描图、PDF 预览图不能被滤镜或遮罩误改颜色。

#### 10.7.4 组件状态规范

浅色和深色都必须覆盖常见组件状态，避免只有静态稿好看、实际交互粗糙。

##### 按钮

- Primary：主操作按钮，浅色为蓝底白字，深色可为蓝底白字或高亮蓝底深字，具体以可读性为准。
- Default：次级按钮，浅色为浅灰底或白底细边框，深色为石墨灰底加深灰边框。
- Dashed：弱操作或占位操作，使用虚线或轻描边，不用于核心流程。
- Hover：移动端不依赖 hover，但在调试、平板、Web 预览中应有轻微背景变化。
- Focus：使用蓝色描边或蓝色外环，不能只改变透明度。
- Active：按下时允许轻微变暗或缩放，但不能影响布局。
- Disabled：降低透明度并禁用点击，同时保留文字可读性。

##### 输入框

- 默认状态：浅色为白底浅灰边框，深色为石墨灰底深灰边框。
- 聚焦状态：边框或光标使用蓝色。
- 错误状态：使用红色提示，但错误文字要具体。
- 禁用状态：降低对比度，不允许看起来仍可编辑。
- 文件名输入框必须在浅色和深色下都能清楚显示光标、选中文本和清除按钮。

##### 卡片

- 浅色卡片使用白色背景、浅灰边框和轻量阴影。
- 深色卡片使用石墨灰背景和深灰边框。
- 卡片之间依靠间距和背景层级区分，不依赖厚阴影。
- 文档卡片中的缩略图必须保持真实颜色，不被主题色污染。
- 卡片 hover 或按下状态只做轻微亮度变化，不改变尺寸。

##### 标签和状态胶囊

- 浅色标签使用浅灰底、深灰文字。
- 深色标签使用石墨灰底、浅灰文字。
- 当前选中标签使用蓝色边框、蓝色文字或蓝色填充。
- 标签高度和圆角要稳定，文字不能贴边。

#### 10.7.5 明暗模式验收标准

- 浅色模式整体效果接近用户参考图中的白色 Apple component kit：高留白、黑色标题、浅灰说明、蓝色主按钮。
- 深色模式整体效果接近用户参考图中的深色 Apple component kit：黑色背景、石墨灰表面、白色标题、浅灰说明、蓝色强调。
- 同一个页面在浅色和深色下信息层级一致，不能因为换主题丢失主操作。
- 所有主要组件至少覆盖默认、按下、聚焦、禁用四种状态。
- 深色页面中，文字、图标、边框、控制点都必须清楚可见。
- 浅色页面中，卡片和背景必须有清晰但克制的层级差异。
- 主题变化不能影响图片处理结果，扫描输出图和 PDF 内容必须保持真实。

### 10.8 动效与反馈

- 页面切换动效简洁，避免夸张弹跳。
- 拍照后进入裁剪页应有短暂过渡或 loading，避免用户误以为卡住。
- 滤镜切换可以使用 100-200ms 的淡入淡出。
- PDF 生成必须显示进度或明确 loading。
- 成功状态使用轻量提示，不使用大面积庆祝动画。
- 删除和导出这类关键操作需要明确反馈。
- 动效不能影响扫描、裁剪、拖动四角的操作精度。

### 10.9 可访问性与可用性

- 所有可点击区域建议不小于 44x44px。
- 文字与背景需要保持足够对比度。
- 重要操作不能只依赖颜色区分，需要结合文字、图标或状态形态。
- 四角拖拽控制点要适合手指操作，不应过小。
- 支持系统字体缩放时，主要按钮和列表文本不得截断。
- 错误提示和权限说明要可读，不使用过浅灰色。

### 10.10 视觉验收标准

- 页面整体观感接近 Apple 系统工具类 App：简洁、留白充足、控件轻量。
- 主要页面不得出现复杂渐变、大面积装饰图形、厚重阴影和营销式大卡片。
- 色板必须优先使用本节定义的颜色，不随意增加品牌色。
- 首页、扫描页、裁剪页、增强页、多页管理页、PDF 导出页都需要有明确的主操作。
- 扫描和编辑相关页面中，图片/文档主体必须是视觉中心。
- Android 真机上文字不能挤压、重叠或超出容器。
- 深色相机页上所有文字和图标必须清楚可读。
- 蓝色强调色只用于主要操作、链接、焦点和选中状态。

## 11. 体验要求

- 扫描入口必须明显。
- 拍照到裁剪确认的等待时间应尽量短。
- 自动识别失败时，不阻断用户继续操作。
- 四角拖动区域要足够大，适合手指操作。
- PDF 导出完成后，要提供明确的“打开预览”和“分享”入口。
- 删除页面和删除文档需要二次确认。
- 删除页面和删除文档在 MVP 阶段不支持撤销。
- 扫描流程被系统中断后，用户再次进入时应尽量提示恢复未确认的临时照片。
- 用户主动放弃扫描或选择不恢复时，应清理未确认临时照片。

## 12. 性能要求

- 单张图片处理时间目标：3 秒以内。
- 20 页以内 PDF 导出应稳定完成。
- 20 页以内文档重新打开、继续编辑和重新导出应稳定完成。
- 处理过程中展示进度或 loading 状态。
- 原图和处理图需要控制尺寸，避免内存溢出。
- 页面缩略图应使用压缩图，不直接加载原始大图。
- 原图保留，用于后续重新裁剪和重新增强。
- 处理图最大边长建议控制在约 2500px。
- PDF 内图片默认使用 JPEG 质量约 85。
- 20 页 PDF 目标体积尽量控制在 20MB 以内，但清晰度优先于极限压缩。
- MVP 不提供“高清 / 标准 / 小体积”等导出质量选项。

## 13. 异常处理

### 13.1 相机异常

- 相机权限被拒绝：提示用户开启权限。
- 相机启动失败：提示用户重试或从相册导入。

### 13.2 图片处理异常

- 边缘检测失败：进入手动框选模式。
- 裁剪失败：提示用户重新调整四角。
- 图片过大：自动压缩后再处理。
- 页面方向无法可靠判断：导出页提示用户选择竖版或横版 A4。

### 13.3 PDF 导出异常

- 页面为空：禁止导出。
- 文件名为空：提示用户输入文件名。
- 文件名重名：弹窗询问用户覆盖原文件或另存一份，另存时可自动追加序号。
- 导出失败：提示用户重试。
- 分享失败：保留本地 PDF，并提示用户稍后分享。
- 重新导出失败：保留上一次成功导出的 PDF，不破坏扫描工程。

### 13.4 本地存储异常

- 本地空间不足：提示用户释放空间后重试，并保留已保存的扫描工程。
- 文档资源缺失：提示用户文件可能已被清理或移动，不直接崩溃。
- 删除文档失败：提示用户重试，并避免出现列表已删除但文件仍残留的不一致状态。
- 本地日志写入失败：不阻断扫描、编辑和导出主流程。

### 13.5 扫描中断异常

- 系统中断、App 切后台或异常退出：已确认加入文档的页面必须保留。
- 未确认裁剪的临时照片：短期保留，并在用户下次进入扫描流程时提示恢复。
- 用户主动取消或选择不恢复：删除对应临时照片。
- 恢复失败：提示用户重新拍摄，不影响已保存文档。

## 14. MVP 验收标准

MVP 可以上线内测的最低标准：

- Android 真机可以完成拍照扫描。
- MVP 最低支持 Android 10 / API 29。
- 至少覆盖 3 台 Android 真机：一台低端或老设备、一台主流中端设备、一台较新设备。
- 支持自动识别纸张边缘。
- 普通 A4 文档场景下，一次识别成功率目标为 80% 以上。
- 支持手动调整四角。
- 支持至少 4 种图像模式：原图、增强、灰度、黑白。
- 支持多页扫描。
- 支持相册多选导入，并逐页裁剪、增强、确认。
- 支持页面删除和排序。
- 删除页面和删除文档前必须二次确认，MVP 不支持撤销。
- 支持历史文档打开、重命名、删除、继续编辑和重新导出。
- 历史页面重新编辑时基于原图重新生成处理图。
- 支持生成多页 PDF。
- PDF 默认使用 A4 页面并保留 10mm 白边，页面方向按扫描图自动选择竖版或横版。
- PDF 文件名重名时，用户可以选择覆盖原文件或另存一份。
- PDF 默认保存在 App 沙盒内，导出完成后可打开预览或分享。
- 支持通过系统分享面板分享 PDF。
- 所有文档和导出的 PDF 默认保存在 App 沙盒内。
- 导出 PDF 后保留扫描工程。
- 用户卸载 App 后，App 沙盒内文件随 App 数据删除，并需要在产品内提示用户提前分享重要文件。
- MVP 阶段不接入远程埋点或远程崩溃上报，仅保留本地非敏感日志。
- 支持用户主动导出本地日志。
- 无需登录即可使用核心功能。
- MVP 首页不提供搜索、筛选或排序切换。
- MVP 不提供自动拍照和导出质量选项。

## 16. 主要风险

### 16.1 边缘识别准确率

复杂背景、阴影、反光、低对比度会影响自动识别准确率。MVP 在普通 A4 文档场景下一次识别成功率目标为 80% 以上，复杂场景不强制达到该比例，但必须提供手动四角调整作为兜底。

### 16.2 性能和内存

高分辨率照片可能导致内存压力。实现时需要保留原图，但将处理图最大边长控制在约 2500px，并避免缩略图、预览图和 PDF 生成过程直接加载过大的原始图片。

### 16.3 React Native 与原生模块边界

扫描能力不适合全部放在 JS 层。MVP 应将图像处理和 PDF 生成放在 Android 原生层，RN 负责页面流程。

### 16.4 后续 iOS 扩展

Android 原生模块不能直接复用到 iOS。接口设计需要提前保持平台无关，避免 JS 层绑定 Android 特有实现。

### 16.5 沙盒存储可见性

PDF 默认保存在 App 沙盒内，用户可能误以为文件已保存到系统下载目录。产品需要在导出完成页、设置页或合适位置说明保存位置，并引导用户通过分享将重要文件转存到其他 App 或位置。

### 16.6 扫描中断和临时文件

临时照片恢复可以降低意外中断造成的数据丢失，但也会增加临时文件清理复杂度。实现时必须区分已保存工程、未确认临时照片和可清理中间文件。

## 17. 成功指标

- 用户从拍照到生成单页 PDF 的流程可以在 30 秒内完成。
- 用户可以在 2 分钟内完成 5 页文档扫描并导出 PDF。
- 自动边缘识别在普通 A4 文档场景下一次识别成功率达到 80% 以上。
- 用户即使在自动识别失败时，也可以通过手动调整完成扫描。
- 内测用户不需要说明书即可完成首次扫描和分享。
- MVP 内测阶段通过人工测试记录和用户主动导出的本地日志采集成功指标。
- 本地日志只用于排查运行问题，不用于远程埋点统计。
